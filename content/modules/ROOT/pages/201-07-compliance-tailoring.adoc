= Meaningful Compliance – Tailoring a Profile
:role: Intermediate Compliance
:skills: Compliance Operator, Tailored Profiles, Remediation
:labid: LAB-201-07
:toc:
:icons: font

**Duration:** ~25 minutes

== Overview
Compliance tailoring & remediation pipeline.

Tailor a Compliance Operator profile so scans match your environment instead of treating every upstream rule as equally required.

== Why it matters
Raw upstream Compliance profiles flag noise your environment cannot fix today. Tailoring keeps scans honest—required controls stay red until fixed; documented exceptions stay visible instead of ignored.

== What does it solve

* Alert fatigue from irrelevant CIS findings
* “Waived forever” exceptions with no ownership
* Audits that cannot explain why a rule was skipped

== Your Mission
Tailor a Compliance profile so attackers and auditors alike face a scan set that matches your real platform—not a one-size-fits-nobody checklist. You already ran `ocp4-cis` audit-log checks in xref:101-10-security-compliance-addons.adoc[101-10]; this lab is how you disable noise and apply remediations on purpose.

=== Prerequisites

* Compliance Operator installed (`openshift-compliance` namespace)
* Cluster admin privileges

Click each step only if you need a hint.

.Apply ComplianceScan baseline-scan
[%collapsible]
====
Start from `rhcos4-moderate` so you have a noisy baseline to compare later.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: compliance.openshift.io/v1alpha1
kind: ComplianceScan
metadata:
  name: baseline-scan
  namespace: openshift-compliance
spec:
  scanType: Platform
  profile: rhcos4-moderate
  contentImage: registry.redhat.io/compliance/openshift-compliance-content-rhel9:latest
  debug: false
EOF
----

TIP: `compliancescan.compliance.openshift.io/baseline-scan created`.
====

.Get ComplianceScans
[%collapsible]
====
Wait until `phase=DONE` before you read remediations.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get compliancescans -n openshift-compliance
----

TIP: `baseline-scan` reaches `DONE`. This can take several minutes.
====

.Get ComplianceRemediations
[%collapsible]
====
These CRs are the hardening knobs the operator can apply.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get complianceremediations -n openshift-compliance | head
----

TIP: A list of rule-named remediations. Empty means the scan is still running.
====

.Grep remediations for chrony
[%collapsible]
====
Pick a real rule id from your cluster. `chrony` is only an example filter.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get complianceremediations -n openshift-compliance | grep -i chrony || true
----

TIP: Copy a rule name you will disable in the TailoredProfile. If chrony is absent, pick another FAIL that is noise for this lab cluster.
====

.Apply TailoredProfile rhcos4-moderate-tailored
[%collapsible]
====
Replace `rhcos4-useless-example` with the rule name you copied. Document why you disabled it in production.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: compliance.openshift.io/v1alpha1
kind: TailoredProfile
metadata:
  name: rhcos4-moderate-tailored
  namespace: openshift-compliance
spec:
  extends: rhcos4-moderate
  setValues: []
  disableRules:
    - name: rhcos4-useless-example
EOF
----

TIP: `tailoredprofile.compliance.openshift.io/rhcos4-moderate-tailored created`.
====

.Apply ComplianceScan tailored-scan
[%collapsible]
====
Point this scan at the tailored profile, not the raw one.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: compliance.openshift.io/v1alpha1
kind: ComplianceScan
metadata:
  name: tailored-scan
  namespace: openshift-compliance
spec:
  scanType: Platform
  tailoredProfile: rhcos4-moderate-tailored
  contentImage: registry.redhat.io/compliance/openshift-compliance-content-rhel9:latest
EOF
----

TIP: `compliancescan.compliance.openshift.io/tailored-scan created`.
====

.Get ComplianceScans to compare baseline vs tailored
[%collapsible]
====
Compare result counts after both scans are DONE.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get compliancescans -n openshift-compliance
----

TIP: Tailored should show fewer failing rules if the disable matched a real check.
====

.Get remediations for the tailored scan
[%collapsible]
====
Find a remediation you are willing to apply on this lab cluster.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get complianceremediations -n openshift-compliance | grep tailored || head
----

TIP: Copy the remediation name for the next step.
====

.Annotate a ComplianceRemediation to apply
[%collapsible]
====
Replace `<name>` with the remediation you copied. Prefer annotate over AutoApply in production.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc annotate complianceremediation <name> compliance.openshift.io/apply=true -n openshift-compliance
----

NOTE: Auto-apply of remediations is for non-prod iterative hardening only—enable it with a change ticket and a rollback plan.
====

== Debrief

Tailoring turns Compliance Operator from noise into signal: compare baseline vs tailored results, then use ComplianceRemediation as a controlled harden path.

What breaks without this:

* Untailored profiles → alert fatigue and ignored findings
* Manual one-off fixes → undocumentable drift from the benchmark

IMPORTANT: tailored profiles, scan comparison, remediation CRs, and cautious AutoApply (prefer non-prod first).

NOTE: document why a check is disabled; re-scan after remediation to prove the close.
