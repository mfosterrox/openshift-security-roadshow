:cis-summary: "Implement automated certificate management and mutual TLS (mTLS) using cert-manager Operator."
:mitre-summary: "Prevents man-in-the-middle attacks and ensures secure service-to-service communication through automated certificate lifecycle management."
:toc:
:icons: font

**Duration:** ~20 minutes

== Overview
Learn how to deploy and configure cert-manager Operator for automated certificate provisioning, renewal, and management. You'll implement mutual TLS (mTLS) between services to ensure authenticated and encrypted communication.

Install cert-manager, issue certificates automatically, and enable basic service-to-service mTLS with verifiable rotation.

== Why it matters
Manual certificate management is error-prone and leads to expired certificates causing outages. Cert-manager automates the entire certificate lifecycle—provisioning, renewal, and revocation—reducing operational overhead and security risks. Mutual TLS adds an extra layer of security by requiring both client and server authentication.

== What does it solve

* Certificate expiration outages
* Manual certificate management overhead
* Unencrypted service communication
* Man-in-the-middle attacks
* Certificate provisioning complexity

== Your Mission
Issue a service certificate with cert-manager so east-west traffic can use identity, not a copied PEM file. You already put TLS on a Route in xref:101-12-enforcing-tls-routes.adoc[101-12]; this lab is the in-cluster certificate object.

Click each step only if you need a hint.

.Get pods in openshift-cert-manager
[%collapsible]
====
Confirm the operator is already running on this cluster.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get pods -n openshift-cert-manager
----

TIP: cert-manager pods should be `Running`.
====

.Get CRD certificates.cert-manager.io
[%collapsible]
====
Without this CRD, `Certificate` objects will not apply.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get crd certificates.cert-manager.io
----

TIP: The CRD exists. If not, install cert-manager Operator from OperatorHub.
====

.Apply ClusterIssuer selfsigned-issuer
[%collapsible]
====
A self-signed issuer is enough to prove issuance. Match the CA to your trust model in production.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: selfsigned-issuer
spec:
  selfSigned: {}
EOF
----

TIP: `clusterissuer.cert-manager.io/selfsigned-issuer created` (or configured).
====

.Create project 201-08-demo
[%collapsible]
====
The Certificate lands in this namespace.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc new-project 201-08-demo
----

TIP: `Now using project "201-08-demo"`.
====

.Apply Certificate example-cert
[%collapsible]
====
`secretName` is where cert-manager writes tls.crt / tls.key. `dnsNames` must match how services will call each other.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: example-cert
  namespace: 201-08-demo
spec:
  secretName: example-cert-tls
  issuerRef:
    name: selfsigned-issuer
    kind: ClusterIssuer
  dnsNames:
  - example.201-08-demo.svc.cluster.local
EOF
----

TIP: `certificate.cert-manager.io/example-cert created`.
====

.Get Certificate example-cert
[%collapsible]
====
Wait until Ready is True.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get certificate -n 201-08-demo
----

TIP: `READY` should be `True`.
====

.Get Secret example-cert-tls
[%collapsible]
====
That Secret is what you mount into pods for mTLS.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc get secret example-cert-tls -n 201-08-demo
----

TIP: The Secret exists and has `tls.crt` / `tls.key` data.
====

== Debrief

cert-manager automates issuance and renewal so expiry outages disappear; mTLS adds service-to-service identity beyond perimeter TLS.

What breaks without this:

* Manual certs → outages at expiry and rushed key handling
* Cleartext or one-way TLS only → lateral sniffing and spoofing between services

IMPORTANT: ClusterIssuer/Certificate CRs, auto-renew before expiry, mTLS where trust boundaries need mutual proof, and protected key material.

NOTE: use public CA, private CA, or self-signed to match your trust model; renewal timing is the reliability win.
