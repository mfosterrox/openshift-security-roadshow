= Policy at the Front Door – Admission Governance (Gatekeeper)
:role: Intermediate Admission Governance
:skills: Admission Control, Gatekeeper, Policy Layering, Governance
:labid: LAB-201-10
:toc:
:icons: font

**Duration:** ~25 minutes

== Overview
Admission governance & policy layering. Enforce baseline safety gates before insecure workloads enter the cluster.

Use Gatekeeper admission policies to block unsafe cluster changes at the API and show clear allow versus deny outcomes.

== Why it matters
Insecure specs enter the cluster only once—at admission. Gatekeeper (and similar) policies turn “we hope teams follow the guide” into denies at the API before a rootful or hostPath payload ever schedules.

== What does it solve

* Workloads that quietly revive root, privileged, or host mounts
* Policy drift between wiki docs and what the API accepts
* Late discovery of unsafe objects already running in production

== Your Mission
Install admission gates that block attacker-shaped pod specs at the door and prove clear allow versus deny outcomes. This is the cluster-side follow-up to digest pins in xref:201-04-shift-left-pipeline.adoc[201-04] and registry allow-lists in xref:101-07-image-provenance-guardrails.adoc[101-07].

=== Prerequisites

* Gatekeeper / OpenShift operator installed (CRDs: ConstraintTemplate, K8sAllowedRepos, etc.)
* Cluster admin privileges

.Apply ConstraintTemplate k8snonrootuid
[%collapsible]
====
The template is the reusable Rego. Constraints instantiate it.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8snonrootuid
spec:
  crd:
    spec:
      names:
        kind: K8sNonRootUid
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8snonrootuid
        violation[{"msg": msg}] {
          input.review.kind.kind == "Pod"
          c := input.review.object.spec.containers[_]
          not c.securityContext.runAsNonRoot
          msg := sprintf("Container %s must set runAsNonRoot=true", [c.name])
        }
EOF
----

TIP: `constrainttemplate.templates.gatekeeper.sh/k8snonrootuid created`.
====

.Apply Constraint nonroot-required
[%collapsible]
====
This turns the template on for the cluster.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sNonRootUid
metadata:
  name: nonroot-required
spec: {}
EOF
----

TIP: `k8snonrootuid.constraints.gatekeeper.sh/nonroot-required created`.

.Apply pod root-pod (expect deny)
[%collapsible]
====
`runAsNonRoot: false` is the attacker-shaped spec.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -n 201-10-a-govern -f - <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: root-pod
spec:
  containers:
  - name: app
    image: registry.access.redhat.com/ubi9/ubi
    securityContext:
      runAsNonRoot: false
    command: ["sleep","5"]
EOF
----

TIP: Admission rejects the pod. A deny message should mention `runAsNonRoot`.
====

.Apply ConstraintTemplate k8snetpolrequired
[%collapsible]
====
This template requires a NetworkPolicy in the pod’s namespace before the pod is admitted.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8snetpolrequired
spec:
  crd:
    spec:
      names:
        kind: K8sNetPolRequired
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8snetpolrequired
        violation[{"msg": msg}] {
          input.review.kind.kind == "Pod"
          ns := input.review.object.metadata.namespace
          not has_network_policy[ns]
          msg := sprintf("Namespace %s lacks a NetworkPolicy", [ns])
        }
        has_network_policy[ns] {
          p := data.inventory.namespace[ns].networkpolicies[_]
        }
EOF
----

TIP: `constrainttemplate.templates.gatekeeper.sh/k8snetpolrequired created`.
====

.Apply pod ok-pod
[%collapsible]
====
Non-root plus a NetworkPolicy in the namespace. The image digest in this snippet is a placeholder—replace it with a real digest from your registry if admission also requires digest pins.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -n 201-10-a-govern -f - <<'EOF'
apiVersion: v1

  name: ok-pod

      runAsNonRoot: true
    command: ["sleep","1000"]
EOF
----

TIP: If digest policy is not on yet, swap the image to a tag for this step only. The next constraint forbids tags.
====

.Apply ConstraintTemplate k8sdigestonly
[%collapsible]
====
Mutable tags are how a supply-chain swap lands after you scanned `:latest`.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8sdigestonly
spec:
  crd:
    spec:
      names:
        kind: K8sDigestOnly
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8sdigestonly
        violation[{"msg": msg}] {
          input.review.kind.kind == "Pod"
          c := input.review.object.spec.containers[_]
          startswith(c.image, "registry.access.redhat.com/")
          not contains(c.image, "@sha256:")
          msg := sprintf("Image %s must use digest", [c.image])
        }
EOF
----

TIP: `constrainttemplate.templates.gatekeeper.sh/k8sdigestonly created`.
====

.Apply Constraint digest-only
[%collapsible]
====
[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -f - <<'EOF'
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sDigestOnly
metadata:
  name: digest-only
spec: {}
EOF
----

TIP: `k8sdigestonly.constraints.gatekeeper.sh/digest-only created`.
====

.Apply pod tag-pod (expect deny)
[%collapsible]
====
`:latest` must fail once digest-only is on.

[source,bash,subs="+macros,+attributes",role=execute]
----
oc apply -n 201-10-a-govern -f - <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: tag-pod
spec:
  containers:
  - name: app
    image: registry.access.redhat.com/ubi9/ubi:latest
    securityContext:
      runAsNonRoot: true
    command: ["sleep","1"]
EOF
----

TIP: Admission rejects the pod because the image has no `@sha256:`.
====

.Label namespace 201-10-a-govern policy-tier=dev
[%collapsible]
====

[source,bash,subs="+macros,+attributes",role=execute]
----

----

TIP: `namespace/201-10-a-govern labeled`.

== Debrief

Admission governance blocks drift before runtime: constraints for non-root, required NetworkPolicy, digest/signing—and exemptions only via explicit, auditable labels.

What breaks without this:

* Policy-only-at-runtime → bad configs already scheduled
* Silent exceptions → untracked risk across teams

IMPORTANT: Gatekeeper/Kyverno (or equivalent) constraint sets, progressive enforce, and labeled exemptions with owners and expiry.

NOTE: admission is the last gate before the API persists the object—pair it with CI scanning so developers fail earlier.
